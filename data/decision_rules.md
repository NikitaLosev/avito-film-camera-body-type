# Правила сборки финальной разметки

Тут описано какие источники меток главнее и почему, плюс известные кривые случаи которые ловятся плохо

## Приоритет источников

Финальная метка для каждой строки в `labels_final.parquet` берётся в таком порядке:

1. **`gold`** (ручная разметка) - 471 строка из `gold.parquet`. Всегда побеждает. Confidence ставим 1.0. Если потом найдём ошибку в gold - правим `gold.parquet` и пересобираем всё с нуля
2. **`kb`** (regex по словарю) - около 55k строк из `kb_labels.parquet`. На gold точность 96.4%, confidence 1.0. Бьёт LLM потому что построен из ручной разметки по ключевым словам с фильтрами на отрицательные слова - идея обычного справочника
3. **`llm`** (Gemini 3.1 Flash-Lite на промпте v3_with_vision) - около 88k строк. Точность 95.8% на отложенной выборке. Confidence берём из ответа модели
4. **`abstain`** (если ничего не сработало) - либо ни один источник не дал метку, либо у LLM уверенность ниже 0.7 $\rightarrow$ `final_label = other_unknown`, confidence = 0.0

## Порог 0.7 для LLM

На пробных прогонах все ошибки модели были с уверенностью 0.85-1.0 - то есть порог по confidence **не лечит ошибки**. Но 0.7 нужен как страховка:
- от случайно вылетевших низких confidence в неожиданных кейсах
- если на проде LLM поставит 0.4 потому что фото мутное - это сигнал что мы не уверены, лучше пометить как `other_unknown`

Порог можно подкрутить после того как посмотрим распределение confidence на всех 88k. Если хвост ниже 0.7 маленький (1-2%) - опустим до 0.5. Если большой - поднимем до 0.8

## Сложные случаи которые модель путает

По результатам v3 на gold:

1. **Skina SK-555 и похожие обманки** - на фото одна модель, в заголовке другая. Текст+картинка тут не помогают, принимаем как есть. Минус 1-2 п.п. точности на компактах
2. **Olympus IS-серия** - снаружи похожа на мыльницу (на самом деле bridge SLR). В gold помечена как SLR, LLM ставит compact. Технически обе версии допустимы - это гибридный класс
3. **"ФЭД-2 комплект полный"** - слово "комплект" триггерит правило про лот, но по факту это просто одна камера с аксессуарами. Пропуск около 0.5 п.п. на дальномерках
4. **Гибридные Instax**: Instax mini Evo (большой LCD сзади) и Instax mini Link / Link 3 (это **принтер**, а не камера) $\rightarrow$ должны идти в `digital_camera` или `accessory_or_part` $\rightarrow$ итоговая метка `other_unknown`
5. **Современные плёночные Polaroid**: Polaroid Go Gen 2, Polaroid Now Gen 2, Polaroid I-2 - это **плёночные** камеры (не цифровые), правильная метка `valid_single_film_camera + instant`. Если есть сомнения - проверяем по официальной странице производителя, Polaroid сами называют их "entirely analog camera"

## Если батч упал

Если при пересборке батчей один из кусков падает с ошибкой:

1. `python retry_chunk.py chunk_NN` - стирает имя батча из state-файла
2. `python batch_submit.py chunk_NN` - засылаем заново (кеш переиспользуется)
3. Стоимость перезапуска около 2.3 доллара за кусок

Если после 2-3 попыток всё равно падает - гоняем этот кусок через обычный синхронный API (дороже, но надёжнее) разовым скриптом. Или собираем итог без этого куска и в `manifest.yaml` пишем что около 8900 строк потерялось

## Ручная проверка результата

После того как собрали `labels_final.parquet`, **обязательно** прогоняем `audit_sample.py`:
- 210 случайных строк со стратификацией по классам (около 35 на класс)
- Руками проверяем глазами в Jupyter, минут 30

Когда колонка `audit_label` заполнена, запускаем `audit_eval.py`, он считает:
- **macro precision** - среднее по точности на класс (не учитывает что классы разного размера в полных 144k)
- **weighted precision** - $\sum$ (точность класса $\times$ доля этого класса в 144k) - это и есть честная цифра точности на всём датасете для отчёта
- **точность по источнику** - отдельно по kb / llm / human / abstain, чтобы понять где главные ошибки
- **точность kb на отдельной выборке** - наш kb построен из gold, поэтому 96.4% на gold это утечка; на ручной проверке получим честную цифру

## Версионирование

Каждый прогон сборки создаёт `manifest.yaml`, в котором лежит:
- sha256 каждого артефакта (raw csv, items, gold, kb, llm, final)
- версия промпта и его sha256
- название модели (gemini-3.1-flash-lite)
- id всех батчей Gemini
- граф родитель $\rightarrow$ потомок

Если пересобираем всё заново (поменяли промпт, появились новые данные) - manifest обновляется, старые артефакты с другим sha256 видны в истории git
